# 11단원 생활 문제 개편 구현 계획

## 확정 범위

- 사용자 요청: 이전 제안의 11.6 ‘친구들에게 응원 보내기’와 11.8 ‘나만의 작은 생활 도우미’를 제외한다.
- 생활 문제 6개와 마지막 읽기 단계 1개로 구성한다. 이전 제안의 간식 가격표는 새 11.6, 마무리는 새 11.7로 표시한다.
- 단원 제목은 ‘실생활 문제 해결’을 유지한다. 중학교 1학년 입문자가 10단원까지 배운 기능을 짧게 복습하며 해결한다.
- 현재는 계획만 작성한다. 콘텐츠·프로그램 변경 및 배포는 구현 요청 이후 진행한다.

## 공통 설명 방식

1. 생활 상황과 질문: 두세 문장으로 무엇을 알아낼지 안내한다.
2. 손으로 예상: 예제의 결과를 짧게 예상하고 바로 확인 가능한 설명을 제공한다. 별도 필수 입력은 만들지 않는다.
3. 짧은 예제: 대체로 4~8줄 이내로 작성하고, 각 줄의 역할을 쉬운 한국어로 설명한다.
4. 실행과 관찰: 예상 출력과 실제 출력을 비교할 위치를 안내한다.
5. 도전: 한 값 변경, 항목 추가, 한 줄 추가 중 한 가지 중심 행동을 요구한다.
6. 힌트: 수정할 줄 → 사용할 기능 → 적용 예시 순서로 제공한다.

- 함수·기호는 앞에서 배웠어도 현재 단계의 핵심 용어에 다시 설명한다.
- 숫자와 문자열을 코드에서 직접 바꾸는 방식으로 진행한다. 새 입력 기능은 필요하지 않다.
- 복잡한 자료 구조 조합, 리스트 컴프리헨션, 함수 정의를 새 11단원의 필수 과제로 넣지 않는다.
- 예제 실행만으로 도전을 완료하지 않는다. 자유 입력 과제는 시작 예시와 다른 유효한 선택을 하도록 안내한다.

## 마지막 읽기 단계 원고 방향

### 우리가 해낸 일

‘시간과 돈을 계산하고, 조건에 따라 다른 안내를 보여 주고, 준비물과 독서 기록을 목록으로 다뤘어요. 간식 이름으로 가격을 찾는 프로그램도 만들었어요.’

### 학습자에게 전할 말

‘처음에는 낯설었던 코드를 읽고, 직접 바꾸고, 결과를 확인하며 여기까지 왔어요. 끝까지 차근차근 해낸 여러분을 칭찬해요! 모든 명령을 외우지 않아도 괜찮아요. 기억나지 않으면 핵심 용어와 예제를 다시 보고, 한 줄씩 실행해 보면 돼요. 작은 문제를 스스로 해결해 본 경험이 다음 도전의 든든한 출발점이 될 거예요.’

- ‘파이썬을 완벽하게 익혔다’ 같은 과장된 평가보다 실행·수정·관찰과 끈기를 칭찬한다.
- 읽기 단계는 기존 읽기 화면을 재사용하고 실행 과제를 표시하지 않는다.
- ‘학습 마치기’ 버튼에 기존 gi-pulse 강조 효과를 적용한다. 클릭 전에는 전체 과정 완료를 선언하지 않는다.
- 완료 후 ‘전체 학습을 마쳤어요!’와 복습 안내를 보여 주며, 마지막 화면에 의미 없는 다음 버튼을 표시하지 않는다.

## 채점 구현 방향

- 기존 `changed`·`contains`만으로 계산의 정확성을 보장할 수 없으므로, 문제별 실제 계산 결과와 출력이 일치하는지 검증하도록 설계한다.
- Python 실행 결과에 연결된 제한된 검증을 우선 검토한다. 필요한 입력값·계산값만 실행 환경에서 확인하고, 임의 JavaScript 실행이나 출력 문자열 하드코딩으로 채점을 대체하지 않는다.
- 단순 정규식으로 특정 변수명·따옴표·공백만 정답으로 강제하지 않는다. 각 도전에서 명시한 핵심 기능 사용과 결과를 함께 확인한다.
- 실행 후 코드를 수정하면 이전 통과 판정을 사용할 수 없다는 기존 동작을 유지한다.
- 힌트 예시, 다른 유효한 이름/금액, 잘못된 계산, 실행 오류, 예제 미수정 상태를 대표 사례로 점검한다.

## 기존 학습 기록 처리

- 새 내용이 기존 11단원과 완전히 다르므로 동일 ID에 예전 코드·완료 상태가 그대로 적용되지 않도록 11단원 콘텐츠 버전을 분리한다.
- 1~10단원 진도와 코드는 보존하고, 이전 11단원 기록은 복구 가능한 별도 기록으로 보관한다. 새 11단원은 새 진행 상태로 시작한다.
- 이전 11단원을 열어 둔 학습자는 새 11.1로 이동하고, 새 생활 문제로 바뀌었다는 짧은 안내를 보여 준다.
- 표시 번호와 내부 ID를 혼동하지 않도록 구현 시 기존 LessonId 타입·저장 키를 검토한다. 진도 수는 현행 필수 레슨 목록에서 계산한다.

## 작업 대상과 구현 순서

1. `chapter11.ts`와 필요하면 별도 11단원 콘텐츠 파일에 7단계를 작성한다. 한 파일 500줄 미만을 유지한다.
2. `lessonGuides.ts`, `codeGlossary.ts`의 기존 축제 준비물 가이드·매핑을 새 단계에 맞춘다. 자동 생성 설명이 새 콘텐츠와 충돌하지 않도록 `lessonFactory.ts`를 확인한다.
3. 문제별 통과 조건과 실행 결과 연결을 구현하고 대표 정답/오답으로 검증한다.
4. `useLearningProgress.ts`, `App.tsx`에서 11단원 버전 전환과 저장된 선택 단계 처리를 구현한다.
5. `LessonWorkspace.tsx`의 최종 읽기 완료 동작을 확인하고 필요한 부분만 조정한다.
6. 업데이트 내역과 관련 콘텐츠·채점 회귀 검사를 갱신한다.

## 검증 기준

- 생활 문제 6개와 마지막 읽기 1개가 순서대로 나타난다.
- 6개 시작 예제와 힌트가 모두 실행되며 설명의 예상 결과와 일치한다.
- 서로 다른 유효 정답을 인정하고, 틀린 계산과 이전 실행 결과는 통과시키지 않는다.
- 마지막 읽기 단계는 실행 없이 완료 가능하고 마지막 완료 수에 정확히 반영된다.
- 기존 1~10단원 기록 보존, 이전 11단원 코드 혼입 방지, 새로고침 후 진도 복원을 확인한다.
- 기존 테스트·린트·타입 검사·빌드를 실행하고, 브라우저에서 대표 실습 및 마지막 완료 흐름과 좁은 화면을 확인한다. VoiceOver 검증은 제외한다.
