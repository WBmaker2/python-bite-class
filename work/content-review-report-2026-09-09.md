# 1~11단원 콘텐츠 점검 결과

점검일: 2026-09-09
대상: `src/content/chapter1.ts`~`chapter11.ts`, `lessonGuides.ts`, `lessonFactory.ts`, `codeGlossary.ts`
기준: 파이썬을 처음 배우는 중학생이 설명을 읽고 시작 코드를 실행한 뒤 도전에 성공할 수 있는지 확인

## 반영한 수정

- 자동으로 덧붙이는 공통 예제는 실제 시작 코드를 사용하고 `시작 코드의 예상 결과`를 기준으로 안내하도록 바꿨습니다. 기존에 작성된 짧은 guide 예제는 유지하되, 그 예제의 예상 결과와 시작 코드의 결과를 섞지 않도록 대상을 분명히 했습니다.
- 공통 예제의 “핵심 줄” 표현을 “시작 코드의 첫 부분부터 전체 흐름을 읽기”로 바꾸었습니다. 첫 줄이 실제 학습 핵심이 아닐 수 있다는 문제를 줄였습니다.
- 공통 목표의 “한 줄을 바꾸어”를 “안내된 부분을 바꾸어”로 바꾸어 여러 줄을 다루는 4.5·11.6에도 맞게 했습니다.
- 8.1은 “함수 이름을 바꾸기”로 오해할 수 있는 지시를 “호출 괄호 안에 실제 값을 넣기”로 고쳤습니다.
- 8.2는 `return`을 먼저 사용하지 않고 함수 안 지역 변수를 `print()`로 확인하는 흐름으로 바꾸었습니다. 8.6에서 보인 `return`을 8.7에서 독립된 핵심 개념으로 다시 설명합니다.
- 8.6은 가변 인수·튜플·`len()`·`sum()`·펼치기가 한꺼번에 나오는 점을 본문에서 인정하고, 출력 한 줄씩 확인하도록 안내를 단계화했습니다.
- 8.8은 문서 문자열을 바꾸라는 지시와 실제 도전 검사가 섞이지 않도록 숫자만 바꾸도록 정리했습니다.
- 9.1은 `math.sqrt()`에 0 이상을 넣어야 한다는 조건을 힌트에 넣었습니다.
- 10.1은 시작 코드가 목록 전체를 출력하지 않는다는 사실을 힌트에 밝혔습니다.
- 10.3은 튜플 자체를 고치는 것이 아니라 새 튜플을 `point`에 다시 넣는 것임을 명확히 했습니다.
- 10.8은 빈 문자열로 바꾸면 `word[0]`에서 오류가 날 수 있으므로 한 글자 이상인 영어 단어를 사용하도록 했습니다.
- 10.9의 “리스트와 딕셔너리 함께”라는 사실과 다른 표현을 딕셔너리 순회 설명으로 고쳤습니다.
- 11.2의 두 번째 지출 범위를 1~3,200원으로 명시했습니다.
- 11.3은 도전 통과 조건(`money < price`)과 같은 금액 경계 관찰을 분리했습니다. `money = 1500`은 추가 관찰이고 도전 통과 예시는 `money = 1000`입니다.
- 6.1은 `a`, `b`를 0보다 큰 정수로 바꾸도록 했고 `b = 0`을 피하라는 문장을 추가했습니다.
- 업데이트 내역에 이번 점검 기록을 추가했습니다.
