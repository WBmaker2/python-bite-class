- 작성일: 2026-09-01
- 실행 모드: `full`
- 대상: `python-edu-starter` / 파이썬 한입 교실
- 대상 학년: 중학생(중1~중3, 13~15세), 한국어
- 핵심 목표: 1. 이 프로그램 소개부터 11. 실생활 문제 해결까지 순서대로 읽고, 실행하고, 도전하고, 다음 학습으로 전이하기
- 검증 경계: 실제 학생 표본·교사 승인·VoiceOver 인증이 아닌 `simulated learner panel` 브라우저 증거

## 플레이테스트 패널

- 주 패널: 중1 민재(14세). 제목과 짧은 문단을 먼저 훑고, 화면에서 가장 눈에 띄는 버튼을 누르며, 코드 오류가 나면 친절한 다음 행동을 기대합니다.
- 인접 가드레일: 초6 서윤(12세)의 긴 문장·전문 용어 부담과 고1 지훈(16세)의 근거·정확성 기대를 짧게 확인합니다.

## 기준선 시나리오

1. 새 브라우저 상태에서 1.1을 읽고 완료 → 다음 학습으로 이동
2. 1.2 학습 방법 → 1.3 교재 출처·라이선스 → 1.4 첫 Python 실행
3. 1.4에서 `print(` 문법 오류 실행 → 오류 도움말·다시 실행·완료 회복
4. 2.1~2.3에서 자유 선택 도전(`자동화` 외 항목) → 통과·다음 단계
5. 각 장의 마지막 단계 완료 후 다음 장 첫 단계가 열리는지 확인
6. 마지막 11.8까지 완료 가능한지, 완료 후 다음 행동·완주 메시지가 있는지 확인
7. 새로고침·진도 초기화·잠긴 단계 직접 선택·업데이트 내역/출처 링크 확인
8. 320×800, 375×812, 768×900, 1280×900에서 같은 핵심 경로를 확인
9. 마우스 없이 Tab/Enter/Space로 목차·탭·실행·완료·다음 버튼을 조작

## 검토할 상태와 관찰 질문

| 상태 | 관찰 질문 | 통과 증거 |
| --- | --- | --- |
| cold start | 무엇을 배우며 첫 행동은 무엇인가? | 10초 안에 현재 단계·첫 버튼을 말하고 실행 |
| read | 읽기 단계에서 코드 탭을 누르면 무엇이 되는가? | 다음 행동이 하나로 수렴하고 빈 화면이 아님 |
| running | 실행 중 무슨 일이 일어나는가? | 로딩·중지·완료가 보이고 중복 실행이 안전함 |
| incorrect/error | 틀리면 어디를 고치나? | 긴 traceback보다 쉬운 원인·재시도 행동을 먼저 찾음 |
| challenge | 무엇을 바꿔야 하는가? | 지시·힌트·판정 조건이 일치하고 여러 정답을 허용 |
| completed | 끝나면 무엇을 누르나? | 완료 상태와 다음 학습 CTA가 명확함 |
| mobile | 설명·실습·결과가 가려지지 않는가? | 가로 넘침 0, 핵심 CTA가 뷰포트·탭 흐름에서 발견됨 |
| keyboard | 포커스 순서와 이름이 이해되는가? | 보이는 포커스와 논리적 Tab 순서로 핵심 경로 완료 |

## 초기 이슈 가설

- `EDU-UX-001` / P2 후보: 375px 오류 상태에서 `.error-help`가 뷰포트 아래에 있어 친절한 회복 안내보다 traceback을 먼저 마주침. 오류 복구 자체는 가능하지만 초보 학습자의 회복 비용이 큼.
- `EDU-UX-002` / P2 후보: 읽기 단계의 모바일 `코드 실습` 탭이 행동 없는 `읽기 단계` placeholder만 보여 다음 행동을 흐림.
- `EDU-UX-003` / P2 후보: 여러 단계에서 지시문·힌트가 “한 줄을 바꾸세요”로 반복되어, 실제로 바꿔야 할 코드 위치와 기대 결과를 다시 찾아야 함.
- `EDU-UX-004` / P3 후보: 중학생 기준으로 `CONCEPT`, `TRY IT`, `GLOSSARY`, `LIVE LAB` 영어 라벨이 한국어 행동보다 먼저 보여 핵심 위계를 늦춤.

## 점검 중 추가 발견 및 상태

- `EDU-UX-005` / P1 발견·해결: 읽기 소단원으로 전환할 때 실습 패널 effect가 부모 완료 상태를 `false`로 덮어써 다음 소단원 이동을 막는 경로가 있었습니다. 읽기 단계는 항상 연습 완료로 유지하도록 수정했습니다.
- `EDU-UX-001` / P2 해결: 오류 도움말을 traceback보다 먼저 보여 주고 `role=alert`를 추가했습니다.
- `EDU-UX-002` / P2 해결: 읽기 단계 모바일에서는 행동 없는 코드 실습 탭을 숨겼습니다.
- `EDU-UX-003`, `EDU-UX-004` / P3 백로그: 기능 차단은 아니므로 다음 콘텐츠·카피 개편 때 구체화합니다.

## 구현 범위 원칙

- P0/P1 또는 핵심 전이를 막는 문제가 있으면 먼저 수정합니다.
- 오류 안내는 기존 안전한 Worker·출력 제한을 보존하고, 학생용 회복 안내를 화면 위쪽으로 재배치하는 최소 수정부터 검토합니다.
- 읽기 단계의 모바일 placeholder는 학습 내용을 다시 보거나 다음 읽기 완료 버튼으로 돌아가는 명확한 안내로 개선할지 비교합니다.
- 기존 `gi-pulse`, reduced-motion, 밝은 테마, 개인정보 비수집, 브라우저 내 실행 계약을 유지합니다.
- 새 Canvas/WebGL/게임형 시뮬레이션은 추가하지 않습니다. 코드 실행은 학습 도구이지 변수 예측·관찰형 시뮬레이션이 아니므로 시뮬레이션 결정은 `not-needed`입니다.
- 이미지 추가는 현재 학습 배너가 이미 맥락을 제공하므로 반복 이미지보다 텍스트·상태 회복 개선을 우선하고, 교육용 사실·정답을 생성 이미지에 맡기지 않습니다.

## 완료 기준

- 같은 시나리오를 수정 전·후 375px/1280px에서 재실행합니다.
- 오류 상태에서 학생 패널이 “무엇이 문제인지”와 “다음에 무엇을 고칠지”를 말하고 실제로 재실행합니다.
- 읽기·실행·도전 단계의 완료/잠금/다음 전이가 끊기지 않습니다.
- 320/375/768/1280px에서 `scrollWidth <= clientWidth`, 핵심 CTA 가림 없음.
- 핵심 버튼에 보이는 포커스와 gi-pulse/reduced-motion 대체가 유지됩니다.
- lint·typecheck·전체 테스트·build 및 브라우저 콘솔 오류 0건.
- 학생용 텍스트 감사 장부, 전후 점수, P0–P3 상태, 미실행 항목을 `work/elementary-webapp-ux-report.md`에 기록합니다.

최종 브라우저 순차 검증과 명령 결과는 `work/elementary-webapp-ux-report.md`에 기록합니다. 전체 69개 소단원 전이는 보조 harness로 재현했으며, 대표 오류 회복·2.3 자유 답은 수동 화면 경로로도 확인했습니다.
