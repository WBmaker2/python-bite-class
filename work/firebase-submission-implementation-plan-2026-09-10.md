작성: 2026-09-10. 사용자 승인 범위: wbmaker01@gmail.com 계정으로 Firebase/Firestore 프로젝트 생성, 추천 구조 구현 시작.

## 확정할 제품 동작

- 기존 GitHub Pages 학습 앱과 교육과정을 유지한다. 앱 배포는 별도 명령 전까지 하지 않는다.
- 상단 로그인(학교·이름 두 필드)은 로컬 프로필 등록이다. 바로 오른쪽에 과제 제출을 둔다.
- 안내: 소속·이름은 로컬에 저장되고 과제 제출 전에는 학생 정보·진도·코드를 전송하지 않는다.
- 입력·실행·로그아웃은 로컬 작업이다. 제출 화면에서 학교·이름·범위를 확인하고 명시적으로 제출한다.
- 프로필별 진도·현재 단계·코드·실행 근거를 분리한다. 기존 비로그인 기록은 명시적 선택으로 최초 프로필에 이관한다. 로그아웃·로컬 삭제와 서버 자료 삭제를 구분한다.
- 단계 상태는 읽기 완료/미시도/성공/실패/수정 후 미실행/과거 완료 및 검증 기록 없음으로 구분한다. 선택 참고는 필수 진도 분모에서 제외한다.
- 제출 시점 코드, 마지막 실행 코드·판정, 마지막 성공 코드(있는 경우)를 함께 보관한다. 기존 성공 코드를 추정해 만들지 않는다.
- 재제출은 새 제출본이며 응답 유실 재시도는 동일 제출 ID로 중복을 방지한다. 서버 접수 확인 뒤에만 성공 표시한다.
- 숨은 교사 진입은 기존 브랜드 영역의 작은 진입 요소 또는 반복 클릭으로 제공한다. 추천안 채택에 따라 실제 보호는 wbmaker01@gmail.com Google 로그인 및 Firestore 권한으로 구현한다. 8582는 필수 보안 수단으로 사용하지 않는다. 인증 대체용 비밀번호를 클라이언트에 넣지 않는다.
- 관리자에서 학생/학교 검색, 최신·과거 제출, 단계별 진도·코드, 개인별 Excel 및 PDF 다운로드를 제공한다. PDF는 한글과 긴 코드를 보존하는 직접 파일 다운로드를 우선하며 불가할 때 인쇄 PDF 방식을 명확히 표시한다.

## Firebase 구성

- 지정 계정의 Firebase 프로젝트를 새로 만든다. 제안 ID: python-bite-class-wbmaker01 (사용 가능 여부 확인 후 유사한 고유 ID 사용).
- Spark 요금제로 시작하고 결제 계정을 연결하지 않는다. Google Analytics는 활성화하지 않는다.
- Cloud Firestore Standard/native, 가능한 경우 asia-northeast3(서울), 기본 DB, 처음에는 프로덕션 잠금 규칙.
- 웹 앱 등록, Firebase Auth 익명 및 Google 제공자 활성화. 승인 도메인에 기존 wbmaker2.github.io 및 로컬 개발 주소를 필요한 범위로 등록한다.
- 학생 익명 인증은 최초 명시적 제출 때만 시작한다. 학생·교사 Firebase Auth 인스턴스를 분리하여 교사 로그인이 학생의 제출 주체를 바꾸지 않도록 한다.
- 교사 권한은 검증된 이메일 wbmaker01@gmail.com + Google 제공자 조건 또는 교사 UID allowlist로 서버 규칙에서 강제한다. 익명 사용자는 자기 제출 생성 및 자기 제출 ID 조회만 가능하며 전체 목록·타인 자료 조회·수정·삭제는 금지한다.
- Cloud Functions 없이 Auth + Firestore로 구현한다. 학생 제출은 오프라인 자동 쓰기 큐를 만들지 않는 HTTP/REST commit 또는 동등한 단발 요청 방식으로 한다. 온라인 재연결만으로 미확인 자료가 전송되지 않아야 한다.
- 원자적인 단일 제출 문서(크기 제한을 엄격히 적용) 또는 원자적 다중 문서 기록 중 검증 가능한 구현을 선택한다. 서버 시각, 소유자 UID, 학교·이름 길이, 제출 스키마·버전, 자료 크기 제한을 강제한다. 학생 보고값은 서버 채점 결과로 표기하지 않는다.
- API key 등 공개 웹 설정과 비밀 자격증명을 구분한다. 서비스 계정 키·OAuth 토큰은 저장소와 출력에 노출하지 않는다.

- 구현 에이전트(gpt-5.6-luna): 학생 프로필·실행 근거·제출·교사 UI·보고서·규칙·관련 테스트 및 통합.
- Firebase 준비 에이전트(gpt-5.6-luna): ego-browser로 계정 확인과 프로젝트/DB/Auth/웹 앱 생성, 실제 설정 연결. 앱 구현 파일과 충돌하지 않게 설정 파일 및 작업 기록만 작성한다. 규칙 배포는 검토된 구현 규칙을 전달받은 뒤 수행한다.

7. Firebase 콘솔 프로젝트 URL, 로컬 확인 URL, 구현/검증/남은 제약을 보고한다. 커밋·푸시·공개 앱 배포는 이번 범위에 포함하지 않는다.
