# 파이썬 한입 교실 구현 계획

- 작성일: 2026-08-31
- 대상: 파이썬과 프로그래밍을 처음 배우는 중학생
- 기준 자료: `byte_of_python.pdf`의 2장 소개부터 11장 실생활 문제 해결까지와 공식 원문·한국어판
- 구현 범위: 1장 프로그램 안내 추가, 2~11장 세부 목차·순차 학습 확장, 정적 웹앱 구현과 로컬 검증
- 제외 범위: 계정, 서버, 학급 관리, 점수 경쟁, 음성 안내/TTS/녹음, 커밋·푸시·배포

## 1. 제품 목표

중학생이 설명을 읽은 직후 같은 화면에서 코드를 고치고 실행 결과를 확인하며, 파이썬의 핵심 문법을 실제 문제 해결까지 연결하도록 한다.

학습 성공 기준은 다음과 같다.

1. 학생이 별도 Python 설치 없이 첫 코드를 1분 안에 실행할 수 있다.
2. 1장부터 11장까지 큰 목차와 세부 목차, 현재 위치와 다음 학습 행동을 항상 알 수 있다.
3. 실행 결과와 오류가 코드 편집기 바로 아래에서 명확하게 구분된다.
4. 각 장에서 최소 한 번은 예제를 직접 수정하거나 도전 과제를 해결한다.
5. 마지막 장에서 요구 사항 분석 → 작은 구현 → 실행 확인 → 개선 과정을 경험한다.

## 3. 공통 수업 단위

각 소단원은 아래 순서로 고정한다.

```text
학습 목표 → 핵심 개념 → 짧은 예제 → 직접 실행 → 한 줄 바꾸기
        → 도전 과제 → 힌트 → 결과 확인 → 다음 학습
```

- 정답을 바로 노출하지 않고 1차 힌트와 예시 결과를 제공한다.
- 실행 횟수나 오답 횟수로 학생을 평가하지 않는다.
- 읽기형은 설명을 읽은 뒤 완료할 수 있고, 실행형은 코드가 정상 실행된 뒤, 확인형은 도전 과제를 통과한 뒤에만 완료할 수 있다.
- 직전 소단원을 완료해야 다음 소단원이 열리고, 한 장의 마지막 소단원을 완료해야 다음 장이 열린다.
- 완료 상태는 되돌리지 않으며, 전체를 다시 시작하려면 `진도 초기화`를 사용한다.
- 중요한 다음 행동 하나에만 `gi-pulse` 강조를 적용한다.
- `prefers-reduced-motion`에서는 깜빡임을 제거하고 정적 테두리 강조로 바꾼다.

## 4. 화면 설계

### 데스크톱(1024px 이상)

```text
┌──────────────┬─────────────────────────────┬────────────────────────────┐
│ 왼쪽 목차    │ 가운데 학습 내용            │ 오른쪽 코드 편집기          │
│ 240~280px    │ minmax(360px, 1fr)          │ minmax(420px, 0.9fr)        │
│              │                             ├────────────────────────────┤
│ 장/소단원    │ 목표·개념·예시·도전         │ 실행 결과 / 오류 / 입력     │
│ 진행 상태    │ 이전·완료·다음              │                            │
```

- 전체 화면 높이를 사용하되 각 영역은 독립적으로 스크롤한다.

- 오른쪽 상단에 실행, 중지, 초기화 버튼을 둔다.
- 출력 창은 표준 출력, 오류, 실행 상태를 색과 텍스트로 함께 구분한다.

- 목차는 접을 수 있는 왼쪽 서랍으로 바꾼다.

- 화면 폭이 부족하면 실습 영역을 아래로 내려 세로 흐름으로 전환한다.

- 실행 후 자동으로 실습 탭의 출력 창을 화면에 보이게 한다.
- 주요 터치 대상은 최소 44px로 한다.

- 개념 일러스트는 첫 화면의 시각적 방향을 잡는 역할로만 사용하고, 코드·수치·사실 도식은 실제 DOM 텍스트로 제공한다.

- 상단: 앱 이름, 현재 장, 목차 토글
- 화면 한쪽: `업데이트 내역` 버튼

## 5. 콘텐츠 모델

학습 콘텐츠는 UI 코드와 분리하고 TypeScript 데이터로 관리한다.

```ts
type LessonId = `chapter-${number}-${number}`;

interface Chapter {
  number: number;
  title: string;
  lessons: Lesson[];
}

interface Lesson {
  id: LessonId;
  chapter: number;
  order: number;
  title: string;
  completion: 'read' | 'run' | 'challenge';
  summary: string;
  objectives: string[];
  concepts: ConceptBlock[];
  starterCode?: string;
  expectedOutput?: string;
  challenge?: Challenge;
  glossary: GlossaryItem[];
  resources?: ResourceLink[];
}

interface ConceptBlock {
  type: 'explanation' | 'tip' | 'warning' | 'example';
  title?: string;
  body: string;
  code?: string;
}

interface Challenge {
  prompt: string;
  hint: string;
  checks?: OutputCheck[];
}

interface OutputCheck {
  mode: 'contains' | 'equals' | 'regex' | 'appended' | 'changed';
  value: string;
  feedback: string;
}

interface ResourceLink {
  label: string;
  href: string;
  note?: string;
}
```

- 장 메타데이터, 소단원 데이터, 용어집을 별도 파일로 나눈다.
- 한 파일이 500줄에 가까워지기 전에 장별 파일로 분리한다.
- 2015년 PDF 문장을 길게 복제하지 않고 중학생용으로 재서술한다.
- 교재 원저자·번역자·원문·CC BY-SA 4.0을 1.3 소단원과 업데이트/출처 화면에 모두 표시한다.
- 코드 예제의 별도 3-clause BSD 조건을 명시하고, 이 앱의 재서술 콘텐츠와 앱 코드의 권리는 교재 라이선스와 구분한다.
- `localStorage` 진도 스키마는 v2로 올리고, 기존 v1의 완료 장은 해당 장 첫 소단원 완료로만 안전하게 이관한다.

## 6. 코드 실행기 설계

### 실행 구조

```text
CodeMirror 편집기
      │ run(code, inputQueue)
      ▼
Python Worker ── Pyodide 초기화/실행
      │ stdout / stderr / result / input-request
      ▼
출력 콘솔 + 학습 피드백
```

- Pyodide는 메인 UI와 분리된 module Web Worker에서 초기화한다.
- 첫 실행 시 `Python 준비 중` 상태와 진행 안내를 표시한다.
- `stdout`과 `stderr`를 줄 단위로 UI에 전달한다.
- 실행마다 이전 사용자 전역 변수를 정리해 수업 간 오염을 막는다.
- 기본 표준 라이브러리만 허용하고 사용자 코드에서 임의 패키지 다운로드는 하지 않는다.

### `input()` 처리

- Worker가 입력 요청을 보내면 출력 창 안에 입력 필드를 표시한다.
- 학생이 Enter를 누르면 입력 큐로 전달하고 실행을 계속한다.
- 입력 대기 중에는 실행 버튼을 비활성화하고 중지 버튼을 유지한다.
- MVP에서 안정적인 동기 입력 처리가 어렵다면, 초기 콘텐츠는 `input()` 없이 실행되도록 하고 입력 예제는 사전 정의 값으로 대체한다. 이 경우 UI에 제한을 명시한다.

### 안전장치

- 실행 제한 시간: 기본 5초
- 제한 시간을 넘기거나 학생이 중지를 누르면 Worker를 종료하고 새 Worker를 만든다.
- 출력 제한: 최대 300줄 또는 30KB, 초과 시 실행 중단과 안내 표시
- 연속 실행 잠금: 하나의 코드만 실행하고 중복 클릭을 막는다.
- 패키지 설치, 네트워크 요청, DOM 직접 접근을 학습 범위에서 제공하지 않는다.
- 오류 원문은 보존하되 흔한 오류는 한국어 도움말로 보충한다.
- 사용자 코드는 서버로 전송하지 않고 브라우저 안에서만 실행한다.
- 진도와 마지막 코드는 `localStorage`에만 저장하며 이름·이메일 등 개인정보를 받지 않는다.

### 오류 도움말

- `SyntaxError`: 괄호·따옴표·콜론 확인
- `IndentationError`: 들여쓰기 칸 수와 블록 위치 확인
- `NameError`: 변수 이름과 정의 순서 확인
- `TypeError`: 서로 다른 자료형의 연산 확인
- `ZeroDivisionError`: 나누는 값이 0인지 확인

## 8. 구현 순서

1. 현재 공개 앱을 읽기 전용으로 진단하고 계획·디자인 시스템 문서를 갱신한다.
2. `Chapter`/`Lesson` 계층 모델과 1~11장 세부 콘텐츠를 장별 파일로 분리한다.
3. 그룹형 목차, 펼치기/접기, 완료·잠금·현재 상태와 장별 진도를 연결한다.
4. 읽기/실행/확인형 완료 조건과 순차 잠금 해제, v1→v2 진도 이관을 구현한다.
5. 1장에 이용 방법과 공식 출처·라이선스 링크를 표시하고 README·업데이트 내역을 맞춘다.
6. 기존 CodeMirror/Pyodide 실행기와 안전장치를 새 단계 모델에 연결한다.
7. 단위 검사, 빌드, 데스크톱·모바일 실제 학습자 흐름을 확인한다.
8. 발견한 문제를 고치고 감사 보고서와 최종 검증 결과를 기록한다.

## 15. 브라우저 실행기의 `__name__` 조건 회귀 수정 계획 (완료, 2026-09-04)

> 상태: 브라우저 실행기 안전장치는 구현 완료했습니다. 9.3의 학생용 실행 도전은 16번 계획에 따라 선택 참고 내용으로 전환했으며, 실행기 내부 호환성은 유지합니다.

### 확인된 문제 (EDU-RUN-001, P1)

- `9.3 __name__ 살펴보기`의 시작 코드 `if __name__ == "__main__":`를 브라우저에서 실행해도 조건문 안의 `print()`가 실행되지 않는다.
- 실행 상태는 `완료`가 되지만 출력창이 비어 있어 학습자가 예제 결과를 관찰할 수 없고, 도전 과제와 다음 단계가 막힌다.
- 실제 브라우저에서 `print(__name__)`를 실행한 결과가 `builtins`였으며, 콘솔 오류 없이 조건이 거짓이 되는 것이 원인이다.

### 수정 범위

1. Pyodide Worker가 사용자 코드를 실행할 때 모듈 전역 공간의 `__name__`을 `"__main__"`으로 초기화한다.
2. 전역 공간 생성 로직을 작은 테스트 가능한 함수로 분리하고, `__name__`이 올바른 값으로 전달되는 회귀 테스트를 추가한다.
3. 기존 출력 캡처·5초 제한·출력 제한·중지 동작은 변경하지 않는다.
4. 공개 배포 전 로컬 실행기와 내장 브라우저에서 `__name__` 호환성, 다른 `print()` 단계의 출력, 9.3 선택 참고에서 9.4로 이어지는 흐름을 확인한다.

### 수용 기준

- `if __name__ == "__main__":` 코드 실행 후 출력창에 `이 파일을 직접 실행했어요`가 표시된다.
- 9.3은 실행 도전 없이 선택 참고로 제공되며, 참고를 건너뛰어도 9.4로 이동할 수 있다.
- `print("hello")`, `import math` 등 기존 실행 예제의 출력과 오류·중지·시간 제한 동작이 회귀하지 않는다.
- TypeScript, lint, 전체 단위 테스트, 프로덕션 빌드와 실제 브라우저 검증이 모두 통과한다.
- 이번 수정에서는 새 패키지 설치, 개인정보 수집, 커밋·푸시·배포를 수행하지 않는다.

## 16. 9.3 `__name__` 학습 부담 완화 계획 (2026-09-04)

### 확인된 콘텐츠 문제 (EDU-CONTENT-001, P1)

- 학생용 9.3의 `if __name__ == "__main__":`는 9.3에서만 직접 다루며, 9.4~9.5와 9.7 및 10~11단원에서는 후속 학습에 사용하지 않는다.
- 브라우저 실습은 현재 코드를 항상 직접 실행하는 구조라서, “직접 실행”과 “다른 코드에서 불러오기”를 비교할 관찰 상황이 없다.
- 현재 9.3 도전은 조건문의 의미가 아니라 `print()` 문장 변경만 검사하므로, 새 개념을 이해하지 않아도 통과할 수 있다.
- `type(...).__name__`(자료형 이름)과 `math.__name__`(모듈 이름)이 다른 문맥에서 등장하므로, 9.3의 실행 가드와 의미를 섞어 설명하면 중1 입문자에게 혼동을 줄 수 있다.

### 수정 범위

1. 9.3을 필수 코드 도전에서 선택형 참고/읽기 단계로 전환하여 다음 학습으로 진행이 막히지 않게 한다.
2. `__name__ = "__main__"` 같은 실행기 내부 설정은 학생용 본문·예제·도전 과제에 노출하지 않는다.
3. 선택형 설명을 남길 경우 “파일을 직접 실행할 때만 안쪽 코드를 실행하게 하는 파이썬의 약속” 수준으로 짧게 안내하고, 브라우저 실습의 범위를 명시한다.
4. 5.6의 `type(...).__name__`과 9.6의 `math.__name__`은 각각 “자료형 이름”과 “모듈 이름”으로 별도 설명해 같은 표기의 다른 쓰임을 구분한다.
5. 9.3이 완료 조건으로 진도 잠금을 만들지 않는지, 9.4 이후 학습과 기존 `__name__` 관련 단계가 회귀하지 않는지 테스트한다.
6. 이번 수정에서는 새 패키지 설치, 개인정보 수집, 커밋·푸시·배포를 수행하지 않는다.

### 수용 기준

- 9.3의 선택형 참고 내용을 읽지 않아도 9.4로 이동할 수 있다.
- 학생용 화면에 `__name__ = "__main__"` 대입 코드가 나타나지 않는다.
- 9.3을 참고로 열었을 때 직접 실행 가드의 뜻과 브라우저 실습의 한계가 중1 입문자 문장으로 설명된다.
- 5.6, 9.3, 9.6의 `__name__` 용례가 서로 다른 뜻임을 확인할 수 있다.
- 선택 참고를 건너뛴 학습자의 필수 진도 수치가 선택 단계를 완료한 것처럼 부풀려지지 않는다.
- 전체 테스트, 타입체크, lint, 프로덕션 빌드와 관련 브라우저 흐름이 통과한다.
