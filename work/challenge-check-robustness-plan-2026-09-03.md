# 도전 판정 안정화 계획

상태: 구현 완료·로컬 검증 완료 (커밋·푸시·배포는 별도 요청)

## 문제

자유롭게 코드를 고치는 `changed` 도전이 실행 결과만 기준 출력과 비교하고 있습니다. 학습자가 연산 과정이나 표현을 바꾸었지만 최종 결과가 같으면, 실제 코드 변경을 했어도 도전이 열리지 않을 수 있습니다.

## 목표

- 6.2 `연산 및 할당 연산자`에서 `+=` 뒤 숫자를 바꾼 실습을 안정적으로 통과시킵니다.
- 같은 `changed` 판정을 사용하는 다른 자유 변경형 단계에도 같은 기준을 적용합니다.
- 공백이나 주석만 추가한 코드는 실질적인 변경으로 세지 않습니다.
- 출력이 비어 있거나 시작 코드와 같은 경우는 계속 실패시킵니다.

## 구현·검증 순서

1. 도전 판정기에 코드 정규화 기반의 실질적 변경 검사를 추가합니다.
2. 최종 출력이 기준과 같아도 실질적인 코드 변경이면 통과하는 회귀 테스트를 추가합니다.
3. 기존 `equals`, `contains`, `appended`, 오류·미실행 판정 테스트와 전체 콘텐츠 감사 테스트를 실행합니다.
4. 실제 브라우저에서 6.2의 숫자 수정과 대표 자유 변경 단계를 확인합니다.

## 범위 밖

명확한 결과를 요구하는 `equals` 단계의 목표값은 변경하지 않습니다. 이번 요청에 배포는 포함하지 않으므로 커밋·푸시·Pages 배포는 별도 요청으로 남깁니다.
