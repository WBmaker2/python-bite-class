# 중학생 관점 실사용자 UX 점검 보고서

- 점검일: 2026-09-01
- 대상 앱: `파이썬 한입 교실`
- 범위: 1. 이 프로그램 소개부터 11. 실생활 문제 해결까지, 69개 소단원
- 실행 모드: `full`
- 관찰 패널: 실제 학생이 아닌 `simulated learner panel`입니다. 실제 학생 표본·교사 승인·VoiceOver 인증 결과로 해석하지 않습니다.

## 결론

핵심 학습 경로는 수정 후 처음부터 끝까지 이어졌습니다. 브라우저 순차 harness가 실제 화면의 읽기·실행·도전·완료·잠금 해제를 거쳐 `69/69`까지 도달했고 실패 전이는 0건이었습니다. 대표 수동 경로에서는 1.4에서 문법 오류를 낸 뒤 오류 도움말을 확인하고 코드를 고쳐 재실행했으며, 2.3에서는 `자동화`를 포함한 새 목록 항목으로 도전을 통과했습니다.

## Stage 0·라우팅

Stage 0은 `ready`였습니다. 선택된 UX 검토 경로는 `design-system`이며, `ui-ux-pro-max`는 현재 호출 가능한 런타임 Skill이 아닌 filesystem-only 상태여서 첫 runtime-available fallback을 선택했습니다. 원문 계약은 `work/elementary-webapp-ux-bootstrap.md`와 계획서에 남겼습니다.

## 단계별 브라우저 경로

| 경로 | 확인 결과 |
| --- | --- |
| 1.1 cold start | 현재 단원·오늘 할 일·`학습 완료` 버튼이 보이고 잠금 목차가 구분됨 |
| 1.2 이용 방법 | `읽기 → 코드 실행 → 도전 결과 확인 → 학습 완료 → 다음 소단원` 순서가 설명됨 |
| 1.3 출처·라이선스 | 원문·한국어판·CC BY-SA 4.0 링크 3개와 앱 권리 구분 확인 |
| 1.4 실행·오류·회복 | `print(` 오류 → 학생용 도움말 → `print("다시 실행")` → 완료 전이 확인 |
| 2.3 자유 답 | 목록에 `자동화`를 추가한 출력으로 통과·완료 전이 확인 |
| 장 경계 | 2장 마지막 완료 후 3.1이 열리고 헤더·목차가 갱신됨 |
| 11.8 완주 | `69/69 학습 완료`, `✓ 학습 완료됨`, 다음 버튼 비활성 상태 확인 |
| 보조 경로 | 새로고침·초기화·잠긴 단계 직접 선택·업데이트 내역·출처 링크 확인 |
| 반응형 | 320/375/768/900/1280px에서 `scrollWidth === clientWidth`; 가로 넘침 없음 |
| 키보드 | Tab 순서와 포커스 링 확인, 모바일 목차 닫기 후 메뉴 버튼으로 포커스 복귀 확인 |

전체 순차 검증은 입력을 자동화한 보조 harness이므로 실제 학생의 자연스러운 오입력·망설임을 대표하지 않습니다. 대신 모든 소단원 전이와 판정 계약을 빠르게 재현하는 회귀 증거로 사용했습니다.

브라우저 증거 스냅샷은 `.playwright-cli/page-2026-09-01T09-08-05-260Z.yml`(cold start·읽기 단계 탭 0개), `.playwright-cli/page-2026-09-01T09-15-15-172Z.yml`(2.3 자동화 도전), `.playwright-cli/page-2026-09-01T09-15-43-668Z.yml`(자동화 통과)에 남겼습니다. 최신 콘솔 로그 `.playwright-cli/console-2026-09-01T09-08-05-113Z.log`에는 React 개발 안내만 있고 오류·예외 항목은 없었습니다.
