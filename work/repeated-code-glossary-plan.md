# 예제 코드의 반복 용어 설명 보완

## 목적
중1 입문자가 이전 단계의 내용을 기억하지 못해도 현재 예제와 실습 코드를 읽을 수 있도록, 사용 중인 기능을 각 단계의 핵심 용어에 짧게 다시 설명한다.

## 범위와 구현 방향
- 1~11단원의 시작 코드와 본문 예제 코드, 도전 힌트의 코드 용어를 함께 점검한다.
- 특히 9.5의 math, dir(), sqrt, pi, in, True/False와 문자열 이름과 실제 함수 호출의 차이를 설명한다.
- print, len, type, round 등 함수, 모듈 도구, 자료 구조 메서드, 반복/조건/연산 기호를 재등장하는 단계에서도 설명한다.
- 기존 자세한 설명은 유지하고, 해당 단계에 필요한 짧은 복습 항목만 중복 없이 결합한다. 일반 문자열이나 변수 이름을 무조건 용어로 추가하지 않는다.
- 유지보수 가능한 공통 용어 정의와 단계별 명시적 연결을 선호한다. 파일당 500줄 미만을 유지한다.
- 학습 목표, 시작 코드, 정답 판정, 진도 정책은 변경하지 않는다.
- 앱 업데이트 내역에 변경 내용을 기록한다.

## 검증
- 9.5 핵심 용어에 sqrt와 pi 의미 및 이름 조회/함수 호출 차이가 표시되는지 확인한다.
- 전 단원에서 실제 코드에 등장하는 재사용 기능의 누락을 점검하고 대표적인 6/8/10/11단원 항목을 검증한다.
- 핵심 용어의 중복을 방지하고 기존 용어 설명이 보존되는지 확인한다.
- 콘텐츠 테스트, 타입 검사, lint, build를 실행한다. 검토 보고서에 보완 범위와 한계를 기록한다.

## 배포 단계
- 지정된 변경 파일과 기존 사용자 변경을 분리해 diff·비밀정보·버전/변경 내역을 검토한다.
- `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`를 fresh checkout 기준으로 통과시킨 뒤 변경을 커밋하고 `main`에 푸시한다.
- GitHub Actions Pages 배포가 성공할 때까지 확인하고, 원격 커밋 SHA·워크플로 실행 URL·공개 Pages 주소와 핵심 정적 자산 응답을 기록한다.

## 역할
주 에이전트는 분석, 계획, 검토를 담당하며 gpt-5.6-luna 에이전트가 콘텐츠와 코드 구현을 담당한다.
